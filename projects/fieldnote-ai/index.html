Engineering note 01RAG / knowledge systems

Building a personal AI library that can show its evidence

Fieldnote AI explores how retrieval, model knowledge and explicit agent boundaries can work together on a small CPU-only VPS.

01

Goal and purpose

Course notes are useful while studying but become difficult to navigate as the library grows. The goal was to make that material queryable without building a chatbot that simply sounds confident. The answer should remain useful when the library has no relevant passage, while clearly identifying claims supported by personal material.

DESIGN QUESTIONHow can an assistant combine model knowledge with personal evidence without confusing one for the other?
02

AI engineering concepts

Retrieval-augmented generation

Relevant information is retrieved at query time and placed into context. The model is not retrained when the library changes.

Semantic embeddings

Text and questions share a vector space, allowing retrieval by meaning instead of exact keywords.

Grounded citations

The model may cite only supplied identifiers. The backend renders only sources referenced by the final answer.

Model routing

The same retrieval pipeline can feed private local Qwen or lower-latency DeepSeek Flash.

Prompt-injection boundaries

Retrieved content is untrusted reference data and cannot redefine the agent role.

Context engineering

Candidate results are deduplicated and limited so the prompt remains focused for a small model.

The browser communicates with FastAPI. FastAPI owns orchestration; Pinecone performs semantic retrieval; Ollama serves the embedding model and local LLM; DeepSeek is an optional generation provider. Provider selection never changes retrieval or citation behavior.

04

From documents to relevant context

The ingestion pipeline extracts PDFs and transcripts, normalizes text and removes duplicate documents and chunks using content hashes. Each chunk carries metadata including course, source type, page, document ID and collection.

mxbai-embed-large creates 1,024-dimensional vectors compatible with the Pinecone index. At query time the harness retrieves a wider candidate set, removes repeated content, limits concentration from one document and sends only the strongest evidence to generation.

05

One agent contract, two models

A versioned AGENT.md defines Fieldnote's role, supported tasks, citation policy, language behavior and safety boundaries. The harness loads it as the system instruction for every provider, keeping product behavior independent from the selected model.

LOCAL QWEN3 4B

Privacy and ownership

Runs on the CPU-only VPS through Ollama. Retrieved context stays outside a cloud answer provider, but generation is slower.

DEEPSEEK V4 FLASH

Speed and capability

Receives the question and selected passages through an API. One observed test answered in 2.3 seconds versus 49.9 seconds locally.

Latency figures are individual observed tests, not a formal benchmark.

06

Production setup

  • FastAPI exposes health, model-registry and chat endpoints.
  • systemd runs one unprivileged worker and restarts it after failure or reboot.
  • Localhost bindings keep FastAPI and Ollama off the public network.
  • Environment files store provider credentials outside Git.
  • Browser-local transcripts preserve visible exchanges without creating model memory.
  • GitHub Actions validates retrieval, provider and agent-loading behavior.

08

What I learned

RAG quality depends as much on document preparation, metadata and context selection as on the final model. A model-independent contract makes provider experiments safer, but prompts alone are not enforcement: credentials, retrieval limits, citation filtering and concurrency remain deterministic application code.
