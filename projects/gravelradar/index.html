Engineering note 02Agents / data / SEO

Building an event platform that researches and improves itself

GravelRadar explores where LLM agents add value inside a production data workflow and where deterministic software should remain in control.

01

Goal and purpose

Gravel events are distributed across organizer sites, social pages and regional calendars. Details change, formats differ and manual research does not scale. The project turns that fragmented information into a structured, searchable product with useful country, region and event pages.

DESIGN QUESTIONWhere should an LLM make a judgment, and where should deterministic code verify and publish the result?
02

AI engineering concepts

Specialized agents

Discovery, data quality and SEO are separate roles with focused goals, tools and output contracts.

Structured generation

Model output is proposed data and must conform to a schema before entering the product.

Model tiering

Fast economical models handle high-volume tasks while stronger models are reserved for harder work.

Deterministic orchestration

A non-LLM promoter controls workflow order, state transitions and publication.

Tool-augmented agents

Agents combine model reasoning with web research, Search Console and PageSpeed measurements.

Closed feedback loop

Observed production performance becomes input for the next prioritization cycle.

The public application is built with Next.js and TypeScript. Agent outputs pass through Zod schemas, scheduled Linux services run the workflows and Cloudflare adds edge protection in front of production.

04

Agent roles and boundaries

AGENT / 01

Discovery

Find candidate events, collect source URLs and propose structured records. It does not directly publish.

AGENT / 02

Quality

Review completeness, compare evidence and flag records that need correction or human attention.

AGENT / 03

SEO

Create useful page content from validated records and performance priorities rather than isolated articles.

CONTROL / 04

Promoter

Deterministic code coordinates state and deployment. It uses no LLM because workflow control should be predictable.

05

Quality before autonomy

The model is not treated as a database writer with unlimited authority. Outputs are parsed, schema-validated and checked against existing records. Stable identifiers and duplicate checks protect the catalogue, while source URLs preserve traceability.

  • Schema validation rejects malformed output.
  • Deduplication prevents a discovered event from becoming a second record.
  • Selective publication separates proposals from production changes.
  • Browser tests verify important public flows after changes.
  • Rate limits and edge challenges reduce automated extraction.
06

From automation to a feedback loop

A scheduled script is automation; an agentic product becomes more useful when outcomes influence the next action. GravelRadar collects search and performance signals, identifies weak or promising pages and directs future quality and SEO work toward measurable needs.

08

What I learned

Useful autonomy comes from bounded responsibilities and strong interfaces, not from giving one model every tool. Structured outputs, deterministic promotion and production measurement make the agents replaceable and the overall product easier to reason about.
